A C compiler in pure Python

C kernels on your numpy arrays, at -O3 speed. No toolchain.

Write a C kernel as a string and call it a few hundred milliseconds later. No compiler, no SDK, no wheels, no build step. In the browser too.

pip install cimo
How it works

Standard library only · CPython 3.9+ and Pyodide · MIT

blur.py
import numpy as np
import cimo

k = cimo.compile(r"""
void blur(int h, int w, const float src[h][w], float dst[h][w]) {
    for (int i = 1; i < h - 1; i++)
        for (int j = 1; j < w - 1; j++)
            dst[i][j] = 0.2f * (src[i][j] + src[i-1][j] + src[i+1][j]
                                          + src[i][j-1] + src[i][j+1]);
}
""")

src = np.random.rand(4096, 4096).astype(np.float32)
dst = np.zeros_like(src)
k.blur(*src.shape, src, dst)   # native code, on your arrays in place

Why

Native code wherever Python runs.

Cython, cffi and C extensions need a toolchain on the user's machine. Numba needs LLVM wheels. cimo parses the C, optimizes it, encodes arm64, x86-64 or WebAssembly itself, maps it into executable memory and hands you a Python callable. Your numpy data is never copied.

browser

Pyodide, JupyterLite, marimo

No compiler in the page. cimo compiles there anyway.

  • Real backend. Instruction selection and register allocation, encoded to machine code in Python. No assembler, no linker.

  • Know why a loop is slow. python -m cimo report says which loops were optimized and what blocked the rest.

Real C, not a subset

C11, with its own C library.

cimo bundles its libc, so a kernel behaves the same on every platform, the browser included.

  • The whole language. Structs, unions, bitfields, pointers of any depth, function pointers, recursion, varargs, VLAs, goto, switch, globals, const tables.
  • Bundled headers. stdio.h, stdlib.h, string.h, math.h, ctype.h, inttypes.h and the freestanding headers. printf writes to sys.stdout, so output lands in your notebook.
  • Hand-written SIMD. GNU vector types for NEON, AVX2 and AVX-512. #pragma omp simd and restrict honored as written.
  • The OS when you need it. Link libc for files, clocks, threads and sockets, or any shared library: zlib, BLAS, the Python C API.

Not supported: inline assembly, setjmp/longjmp, 128-bit long double. Each is a compile error that says so.

Pythonic runtime

Plain threads. Python exceptions.

Kernels release the GIL and are safe to call concurrently. No launch API; bring your own threads. malloc is lock-free, with a heap per thread.

16 threads, one kernel
from concurrent.futures import ThreadPoolExecutor

n = 16
with ThreadPoolExecutor() as pool:
    list(pool.map(lambda b: k.blur(b, n, h, w, src, dst), range(n)))

assert, abort(), exit() and traps unwind back to Python. Debug builds bounds-check every access and catch use-after-free, double free and leaks.

Runs in the browser

The same compiler emits WebAssembly.

In Pyodide, JupyterLite or marimo, kernels compile in the page and link into Pyodide's own memory. They work on numpy arrays in place. No server, no 50 MB clang-in-WASM download.

cproc and QBE are ported to Python and checked against the originals by diffing their IR pass by pass. Every release is differential-tested against gcc and clang on generated random programs.
