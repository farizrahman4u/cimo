A C compiler written in pure Python.

cimo compiles C to native code at runtime and calls it on numpy arrays. No compiler, SDK or LLVM needed: it runs wherever CPython or Pyodide does, including this page.

  Usage
  
C kernels from Python

  

    

      
Compile a string or a .c file. Every non-static function becomes a Python callable, typed from its C signature. Arrays are passed by pointer and never copied.

      
    
        
  • Scripts and notebooks. The same call in a script, Jupyter, JupyterLite or marimo.
    • 
        
  • Cached. The second run of the same source starts instantly.
    • 
        
  • Buffers in place. numpy arrays, bytearray, memoryview and ctypes arrays.
    • 
      

    

  

    

      

    
blur.py


import numpy as np
import cimo

k = cimo.compile(r"""
void blur(int h, int w, const float src[h][w], float dst[h][w]) {
    for (int i = 1; i < h - 1; i++)
        for (int j = 1; j < w - 1; j++)
            dst[i][j] = 0.2f * (src[i][j] + src[i-1][j] + src[i+1][j]
                                          + src[i][j-1] + src[i][j+1]);
}
""")

src = np.random.rand(4096, 4096).astype(np.float32)
dst = np.zeros_like(src)
k.blur(*src.shape, src, dst)   # native code, on your arrays in place

# numpy: the same result, bit for bit, 1.6x slower (Linux arm64)
ref = np.zeros_like(src)
ref[1:-1, 1:-1] = 0.2 * (src[1:-1, 1:-1] + src[:-2, 1:-1] + src[2:, 1:-1]
                              + src[1:-1, :-2] + src[1:-1, 2:])
assert np.array_equal(dst, ref)

  Motivation
  
Native code at runtime, without a toolchain

  
Compute-graph engines, PDE solvers and symbolic code generators emit C at runtime and call the system compiler on the user's machine. Where there is none, they fail or fall back to slow paths. Numba avoids the compiler by bundling LLVM. cimo is a compiler written in Python: any machine that runs Python can compile and run C.

  Language
  
C11 and a bundled C library

  
cimo ships its own libc, so kernels behave the same on every platform, including the browser.

  

    

      
    
        
  • Language. Structs, unions, bitfields, pointers of any depth, function pointers, recursion, varargs, VLAs, goto, switch, globals, const tables.
    • 
        
  • Headers. stdio.h, stdlib.h, string.h, math.h, ctype.h, inttypes.h and the freestanding headers. printf writes to sys.stdout, so output appears in notebooks.
    • 
        
  • SIMD. GNU vector types for NEON, AVX2 and AVX-512. #pragma omp simd and restrict honored as written.
    • 
        
  • System libraries. Link the host libc for files, clocks, threads and sockets, or any shared library such as zlib, BLAS or the Python C API.
    • 
      

      
Not supported: inline assembly, setjmp/longjmp, 128-bit long double. Each is a compile error that says so.

  Runtime
  
Threads and error handling

  

    

      
Kernels release the GIL and are safe to call concurrently. There is no launch API; use ordinary Python threads. malloc is lock-free, with a heap per thread.

      

        
16 threads, one kernel


from concurrent.futures import ThreadPoolExecutor

n = 16
with ThreadPoolExecutor() as pool:
    list(pool.map(lambda b: k.blur(b, n, h, w, src, dst), range(n)))

      

    

    

      
assert, abort(), exit() and traps unwind back to Python. Debug builds bounds-check every access and catch use-after-free, double free and leaks.

  WebAssembly
  
Running in the browser

  
In Pyodide, JupyterLite and marimo, cimo compiles C to WebAssembly in the page and links it into Pyodide's memory, so kernels work on numpy arrays in place. The demo at the top of this page is cimo doing exactly that.

  
In a notebook: await micropip.install("cimo"), then cimo.compile(src) as anywhere else.

  Design
  
Architecture

cproc and QBE are ported to Python and checked against the originals by diffing their IR pass by pass. The loop optimizer and machine-code encoder are new. Every release is differential-tested against gcc and clang on generated random programs.
